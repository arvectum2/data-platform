# GitHub private repository connector

`github_repository` is the first concrete customer-authenticated connector built on DP-CRED-001.

## Credential schema

Encrypted `secrets`:

- `token` — GitHub access token accepted by the GitHub REST API.

Open credential metadata:

- `repository` — required `owner/repo` scope;
- `ref` — optional branch, tag or commit reference.

No API base URL, arbitrary host or arbitrary headers are accepted from credential metadata.

## Security model

The connector sends Authorization only to `https://api.github.com` over HTTPS. It rejects URL-embedded credentials, non-default ports and any final URL outside `api.github.com`. Credentialed redirects are refused rather than forwarding Authorization to another host.

Search results are also scoped back to the configured `owner/repo`. File acquisition does not trust an API URL returned by search: it rebuilds the GitHub contents endpoint from the validated repository and path.

Tokens never appear in `DiscoveredResource`, provenance metadata, API responses, error strings or logs generated by the connector.

## Capabilities

`discover` performs repository-scoped GitHub code search and returns GitHub file pages as canonical resources.

`fetch` retrieves the selected file through the GitHub repository contents API using the raw media type, then returns text to the normal Data Platform ingest/chunk/embed path.

`research` accepts the same `credential_id`; for credential-aware sources it uses connector fetch rather than unauthenticated URL ingest, so private files can flow through discovery -> acquisition -> indexing -> hybrid retrieval -> grounded synthesis without exposing the token.

## Operational limits

- code search page size: 1..100;
- pagination cursor: bounded integer page;
- search response cap: 2 MB;
- raw file fetch cap: 5 MB;
- connector retry/rate-limit behavior uses the standard ConnectorPolicy;
- GitHub search pagination is bounded to the first 1000 reported matches.

Binary/large-repository ingestion is intentionally not a goal of this connector. The first version targets code and text files useful for private knowledge/research workloads.

## Production activation

The connector is registered by default but is inert without a tenant-scoped managed credential. Production can therefore deploy the connector code safely before any real GitHub token is stored.

A live private-repository acceptance requires a user/customer GitHub token with access to the chosen repository. No token is generated, scraped from local Git tooling or inferred by Data Platform.
